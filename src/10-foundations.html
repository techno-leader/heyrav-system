Nesting

Corners inside corners are concentric. The inner radius is the outer radius minus the gap between the two edges: a --r-lg shell (20) with an 8px gap holds a 12px corner, so the space between the curves stays even all the way round. The same radius inside and out makes the gap fat at the corners and thin on the sides.

In CSS the rule is the .nest utility: set the shell's radius and gap, and every direct child takes the difference.

nested corners
.nest { --nest-r: var(--r-lg); --nest-gap: var(--s-2); }
/* children: border-radius: calc(var(--nest-r) - var(--nest-gap)) */

Components follow it the same way: a segmented control's selected item is --r-sm minus its 3px inset, a menu item is --r-md minus the menu's padding, and a device screen is --r-device minus its 2px edge. When the gap is as large as the outer radius or larger, the curves no longer read together; the inner element takes its own token from the scale.

Easing

Curves

Each curve plots progress against time. The dashed line is linear; the handles are the two control points of the cubic-bezier. A steep start means the movement leaves quickly; a flat end means it settles. Play sends a dot along each curve at the same speed as the tracks above.

Durations

Every duration, named by role and drawn to scale. Play runs a dot across each bar in exactly that time, on the house curve.

Slow motion

At full speed, a wrong easing or origin hides inside 200ms. Slowed to a tenth, it shows. The control below sets the speed for every animation on the page - transitions, keyframes and the Web Animations API - and S toggles between full speed and the last slow one. Pages whose components move carry the same control under their title.

 
<!-- any element; heyrav.js wires it -->
<button data-speed="0.25">.25X</button>

heyrav.speed(0.1);   // set
heyrav.speed();      // read

// canvas or rAF loops
addEventListener('heyrav:speed',
  e => clock.rate = e.detail);
  • Check every new animation at .1X before it ships. Look for the origin, the first and last frames, and any two properties that finish at different times.
  • Canvas and rAF loops opt in. CSS and the Web Animations API follow automatically; a hand-written loop multiplies its frame delta by heyrav.speed().
  • The shortcut only exists where a speed control is on the page, so linking heyrav.js never takes over a key on its own.

Rules

  • Entry only. Reveals play once as content arrives and never again on scroll back.
  • Cursors do not ease. The hero's pixel hand moves with steps(1,end) - smooth reads as a floating illustration.
  • Two animations do not compose transform. Split them across nested elements.
  • Reduce removes motion, not meaning. The nav still tucks and the loader still runs - each in one frame.

Where sound goes

Every interaction in the system that carries a sound, sorted into three weights. The controls play the voice picked in the bar. Under each one, the same cue in all four voices.

  • Touch - a control changed state under the finger. Shortest and quietest: under 80ms, about half volume.
  • Move - something opened, closed or changed place. Under 250ms.
  • Result - work finished or failed. The only weight allowed a tail, and still under 600ms.

Silent on purpose

  • Hover and focus. They happen dozens of times a minute without intent. A sound there turns into noise within one page.
  • Scroll, reveals and the nav tuck. Motion already says it; sound would say it twice.
  • Links that change the page. The new page is the feedback.
  • Typing. The keyboard already makes its own sound.
  • Tooltips, the progress comet, the loader. Ambient information, never an event.
  • Anything nobody did. Autoplay, timers and background saves. Sound follows a hand, not the system.

Rules

  • Off until asked. The speaker at the foot of the sidebar turns sound on for the whole site and is remembered per device. Until then no page but this one loads any sound. Worlds with their own ambience (Sunken, Aurora) keep their own switch for it.
  • One voice per world. Every cue in a world comes from its voice. A second pack only fills a cue the first has no sound for.
  • One result per action. A copy that also raises a toast is heard once.
  • Never alone. Every sound has a visible change at the same moment. Muted, nothing is lost.
  • Never twice in 40ms for the same cue, so a dragged slider or a held key stays clean.
  • Nothing while the tab is hidden, and a soft limiter on the master bus so two cues together never clip.
  • Phones obey the ring switch. On iOS a silenced phone mutes the page too. That is correct.

Components carry no sound code. One script listens to what they already do (a click, a change, a dialog opening, a toast arriving) and answers in the current world's voice.

<script src="js/sound-ui.js" defer></script>
<button data-snd-toggle aria-pressed="false">…</button>  <!-- the visitor's switch -->

HRSoundUI.cue('success');   // a cue the page cannot see, in the world's voice

The rule

.icon{width:1em;height:1em;fill:currentColor;flex:none;vertical-align:-.125em;}
Mono label Body text Button

Rules

  • Fetch the real path, never hand-write it: curl -sL https://raw.githubusercontent.com/phosphor-icons/core/main/assets/regular/<name>.svg
  • Parents are usually inline-flex, which drops the whitespace between icon and label - add gap (10px body, 6px mono).
  • → in a range (2022 → 2023) is prose, not an icon. Metrics use a capital X, not ×.
  • Decorative icons get aria-hidden="true"; an icon-only button gets aria-label.
  • Optical centring beats box centring: the play triangle moves back 0.037em because its box sits right of its centroid.

Grayscale grade

The closing grid shows ten assets grayscale at rest. A flat grayscale(1) made logos read as black holes next to a white ad (mean luminance 56 to 226), so each tile carries a per-asset --grade that pulls the set to 138-168. Colour returns, ungraded, on hover.

Illustration

Image hygiene

  • Always pair width/height attributes with height:auto - the attributes are presentational hints that beat aspect-ratio.
  • Lazy-load below the fold; never force eager loading to make a check pass.
  • Alt text says what the image proves, not what it looks like.

Contrast

Every text colour clears 4.5:1 on paper in both themes - the ratios are computed at build time and printed on the Colour swatches. 12px mono labels use --ink-3 (5.1:1), not --mut.

Targets

44 × 44px minimum on everything interactive. The padding lives on the link, not the bar, so the target is real. Where art is smaller (the 32px footer lockup), min-height:44px keeps the hit area legal.

Focus

Chip

outline:2px solid var(--ink); outline-offset:2px, on :focus-visible only. A tucked nav returns on :focus-within so keyboard focus is never stranded off-screen.

Semantics

  • Toggles are <button>, not <a href="#"> - a link to # scrolls to the top, and a button gives Enter/Space and focus for free.
  • Hidden layers use visibility, not just opacity, or a screen reader reads both at once.
  • Hover-revealed content is gated in @media (hover:hover); touch browsers leave a sticky hover on the last tap.
  • Dialogs use native <dialog> with showModal(): focus trap, Escape and inert background come from the platform.
