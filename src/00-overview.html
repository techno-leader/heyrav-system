Status, at a glance

Every component carries one of three labels, shown on its page and as a dot in the sidebar.

ShippedLive on heyrav.in. The CSS here is ported verbatim from the page that ships it, and the page links to where you can see it.
In toolsLive in the heyrav tools UI (control rails, sliders, toggles). Same tokens, denser sizes.
SpecDefined here first, built from the same tokens, ready for the next page that needs it. Not on the site yet.

1. Neutral first, colour only where it means something

The whole interface is a single grey ramp. Colour appears in exactly four deliberate places - the aurora hero, the pointer gradient on case illustrations, text selection and the hero word's glitch - plus status colours where a form genuinely needs to say ok, careful or wrong. If colour does not carry information, it is noise.

2. One of everything

One button form (the solid ink pill). One elevation (--shadow-pop). One hairline colour. One reveal curve. When two components do the same job, they share one pattern - a second variant has to argue for itself.

3. Stepped, never fluid

Type and spacing step down at 900 and 640px rather than sliding through clamp(). A clamp renders sizes that are not on the scale (59.4px at 900 wide), which defeats the point of having one.

4. Read, not clicked - and the difference is visible

Cards and figures that are only read get a flat surface, a hairline and no hover state. Anything clickable gets a 44px target and a hover that strengthens (ink goes darker, borders go darker) - never one that makes the control paler under the cursor.

5. Measure, do not eyeball

Contrast ratios are computed, lightness steps are measured in L*, webfonts are proven with width probes, and every colour in the system lists its ratio. Decisions here cite a number or a bench, not taste alone.

6. Calm motion, always optional

Motion settles (--ease-out), plays once on entry, and has a reduced-motion branch that removes it without removing meaning. Loading and layout responses still happen - they just happen in one frame.

Link it

Everything - tokens and components - is one file. Load Onest from Google Fonts; Redaction 35 is declared inside the stylesheet and comes from jsDelivr.

index.html
<link href="https://fonts.googleapis.com/css2?family=Onest:wght@400..600&display=swap" rel="stylesheet">
<link rel="stylesheet" href="https://system.heyrav.in/heyrav.css">
<script src="https://system.heyrav.in/js/heyrav.js" defer></script>

heyrav.js is optional: it only wires the interactive pieces (popovers, tabs, dialogs, toasts, reveal, count-up, the scroll comet). Everything static works on CSS alone.

Dark theme is opt-in

heyrav.in is light-only today, so linking the stylesheet can never flip a page by itself. Dark values are defined for every colour token and switch on with an attribute:

<html data-theme="dark">

The docs you are reading run on the same contract - the theme switch in the sidebar sets that attribute.

Naming

  • Token names are the ones heyrav.in already uses (--ink, --mut, --r-md, --t-body), so pages can adopt the file without renaming anything.
  • New scales are self-describing: --s-N is N × 4px, --d-* durations are named by role (fast, base, move, slow, reveal).
  • Shipped class names are kept verbatim (.case-link, .impact, .define-t). New components get plain names (.btn, .badge, .menu), and where a shipped class is an instance of a new one it is listed as an alias.

Changing a token

Edit tokens/tokens.json, run node build.mjs. The build regenerates the CSS, every swatch and table in these docs (contrast ratios included), the search index and the sitemap. No dependencies.
